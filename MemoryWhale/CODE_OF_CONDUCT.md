# MemoryWhale Code of Conduct

MemoryWhale is a project about preserving technical memory. The collaboration
around it should preserve something similar: context, respect, and care for the
work people are trying to do.

## Our Standard

Everyone participating in this project is expected to:

- Be respectful and direct.
- Assume good faith, but correct mistakes clearly.
- Critique code and ideas, not personal worth.
- Explain tradeoffs when disagreeing.
- Preserve context instead of erasing it.
- Make room for learning, especially around systems, Rust, robotics, and AI.

## Unacceptable Behavior

Unacceptable behavior includes:

- Harassment, insults, or personal attacks.
- Dismissive comments about someone's background or experience level.
- Sharing private logs, secrets, credentials, or personal data without consent.
- Intentionally destructive changes.
- Misrepresenting what the software can do.
- Pressuring others to use unsafe or privacy-invasive workflows.

## Privacy and Logs

This project deals with terminal output, error logs, and project context. Those
records can contain secrets or sensitive details.

Contributors should:

- Avoid posting private logs publicly unless they are scrubbed.
- Remove tokens, keys, passwords, hostnames, and private paths when sharing
  examples.
- Treat command history as potentially sensitive.
- Prefer synthetic examples in documentation.

## Enforcement

Project maintainers may remove comments, reject contributions, or block
participants who violate this code of conduct.

The goal is not bureaucracy. The goal is to keep the project useful, safe, and
serious enough for people to trust it with their technical memory.
