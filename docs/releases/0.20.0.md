# MemoryWhale 0.20.0 — Agents Learn from Each Other

**Release date: October 14, 2026**

**Product: 0.20.0 · Rust core: 0.10.0 (unchanged) · SQLite schema: 14**

A fix found by one agent, or by you at the prompt, now reaches every other
agent on the machine, and it comes with evidence: how often it worked, who ran
it, and when. Recall notes stop guessing. A fix seen to work more than once is
a `confirmed fix`; one seen once stays a `possible fix`. And MemoryWhale now
measures its own notes: shown, followed, worked.

The CLI, web UI, and desktop app use product version **0.20.0**.
`memorywhale-core` stays **0.10.0**. Opening a store migrates it to schema
**14**, which adds one table.

## Install or upgrade

Prebuilt binaries cover Linux x86_64/aarch64 and macOS. The installer resolves
the current published release and verifies its published checksum:

```bash
(
  set -eu
  installer="$(mktemp)"
  trap 'rm -f "$installer"' EXIT
  curl -fsSL https://raw.githubusercontent.com/wuisabel-gif/MemWhale/7c3864c743cec9a8fa813dcc0b2459cc2859c849/install.sh -o "$installer"
  printf '%s  %s\n' '3e0cad72b29c1894d5ff5f7c30b099537f96501801c14b6320c12e169a3ac8d6' "$installer" | shasum -a 256 -c -
  sh "$installer"
)
```

To request this exact CLI release from crates.io after it is published:

```bash
cargo install memorywhale-cli --version 0.20.0 --locked
```

Or use Homebrew:

```bash
brew tap wuisabel-gif/memorywhale https://github.com/wuisabel-gif/MemWhale
brew install memorywhale
# If already installed:
brew update
brew upgrade memorywhale
```

The installer and Homebrew track their published release metadata rather than
pinning this document's version; check what was installed. Make sure the chosen
binary directory is on `PATH` (`~/.local/bin` for the installer or
`~/.cargo/bin` for Cargo):

```bash
mw --version
mw doctor
```

From a source checkout, build all helpers from the repository root:

```bash
cargo build --release -p memorywhale-cli --bins
```

The CLI does not require the desktop shell's GTK/WebKit libraries. Windows
users can use WSL. See [Getting started](../guides/getting-started.md) and the
[Linux guide](../../linux/README.md) for platform setup and Debian packaging.

## What changed

### Fixes that prove themselves (#415)

Until now a recalled fix was the first different command that passed after the
most recent failure, with no check that the failing command then passed.
MemoryWhale now looks at every recorded episode of the error, takes the next
different passing command from each, and counts the episodes in which the
failing command passed afterwards. Candidates are ranked by that count:

```text
MemoryWhale: this error was seen 3 times; worked 2 of 2 times, last run by Codex 2 days ago, confirmed fix: xcode-select --install. Check whether it applies here.
MemoryWhale: this error was seen 2 times; worked once, run in a terminal 3 h ago, possible fix: brew install cmake. Check whether it applies here.
```

`confirmed fix` means the same command was observed to work in two or more
episodes. `possible fix` means once, or not yet. A command that ran after the
failure but was never followed by a pass sinks below one that was.

### Agents learn from each other (#415)

Every capture already carried the agent that produced it; the note now says
so: `last run by Claude Code`, `run by Gemini CLI`, or `run in a terminal`
when you fixed it yourself at the prompt. Commands captured by an agent hook
(`cargo build` as one argument) and at a prompt (`cargo`, `build`) are
compared as the same command line, so a failure in one place and a fix in
another count as one episode.

### Recall stats (#415)

Each fix note shown to an agent is recorded (`recall_hints`). From the runs
that follow, MemoryWhale reads back whether the suggested command ran within
the next ten runs in that directory (followed) and whether the failing command
then passed within twenty (worked). It is reported in:

- `mw doctor`: `recall notes: on: 12 shown to agents, 9 followed, 7 worked`
- the dashboard, as one line under the search box
- the MCP `stats` tool: `recall.hints_shown`, `recall.followed`, `recall.worked`
- `mw context --last-error`, which adds a `Recall:` line with the best fix

Nothing is counted from anyone's claim; only from the recorded exit codes.

### Delphin 0.5.2

[Delphin](https://github.com/wuisabel-gif/Delphin) 0.5.2 reads the
`confirmed fix:` form for `:fix`, alongside `possible fix:` and the older
`the fix was:`.

## Upgrade and compatibility

- Opening a store migrates it from schema 13 to 14: one new table,
  `recall_hints`, whose rows are deleted with the command run they belong to.
  Nothing else changes.
- `memorywhale-core` is unchanged at 0.10.0.
- Tools that parse recall notes: the fix command is still last, after
  `possible fix:` or the new `confirmed fix:`. `fix_candidates`, `Failure`,
  `FixCandidate`, `recall_stats`, `RecallStats`, `ran_by`, and
  `relative_age` are new public items in `memorywhale-cli`.

## What this release does not promise

- "Confirmed" means observed to work in at least two episodes, within a
  window of the next few runs. A command that happened to run in that window
  can still get credit; the ranking makes that less likely, not impossible.
- Stats count only notes returned through capture hooks. Hints Delphin asks
  for with `mw hint` are not tracked.
- The integrations marked "not yet verified live" above are tested against
  their documented or source-level payloads, not in a real session.
