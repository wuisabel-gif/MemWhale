# MemoryWhale 0.14.0 — Relevance-First Recall

**Release date: September 30, 2026**

**Product: 0.14.0 · Rust core: 0.8.0 · SQLite schema: 13**

0.14 makes search rank by relevance first. Until now recency counted the same
for every query, so a newer but weaker match could outrank the memory you were
looking for. Now recency only takes over when you ask about time ("the most
recent sqlite error", "what broke 3 days ago"); otherwise it just breaks ties.
We found the problem, and measured the fix, on a public benchmark.

The CLI, web UI, and desktop app use product version **0.14.0**.
`memorywhale-core` is **0.8.0** (adds `scorer::asks_about_recency` and
`scorer::RECENCY_TIEBREAK`). Existing databases stay on schema **13**; there is
no migration.

## Install or upgrade

Prebuilt binaries cover Linux x86_64/aarch64 and macOS. The installer resolves
the current published release and verifies its published checksum:

```bash
(
  set -eu
  installer="$(mktemp)"
  trap 'rm -f "$installer"' EXIT
  curl -fsSL https://raw.githubusercontent.com/wuisabel-gif/MemWhale/7c3864c743cec9a8fa813dcc0b2459cc2859c849/install.sh -o "$installer"
  printf '%s  %s\n' '3e0cad72b29c1894d5ff5f7c30b099537f96501801c14b6320c12e169a3ac8d6' "$installer" | shasum -a 256 -c -
  sh "$installer"
)
```

To request this exact CLI release from crates.io after it is published:

```bash
cargo install memorywhale-cli --version 0.14.0 --locked
```

Or use Homebrew:

```bash
brew tap wuisabel-gif/memorywhale https://github.com/wuisabel-gif/MemWhale
brew install memorywhale
# If already installed:
brew update
brew upgrade memorywhale
```

The installer and Homebrew track their published release metadata rather than
pinning this document's version; check what was installed. Make sure the chosen
binary directory is on `PATH` (`~/.local/bin` for the installer or
`~/.cargo/bin` for Cargo):

```bash
mw --version
mw doctor
```

From a source checkout, build all helpers from the repository root:

```bash
cargo build --release -p memorywhale-cli --bins
```

The CLI does not require the desktop shell's GTK/WebKit libraries. Windows
users can use WSL. See [Getting started](../guides/getting-started.md) and the
[Linux guide](../../linux/README.md) for platform setup and Debian packaging.

## What changed

### Retrieval: query-aware recency

- **Relevance first** (#359): recency keeps full weight only when the query
  asks about time: "recent", "latest", "yesterday", "today", "ago", or
  "last"/"this"/"past" before a period ("last week", "last 3 days", "this
  morning"). Otherwise it keeps a tenth of its weight and only orders near-ties.
  `mw search --explain` marks those cases "tie-breaker only". This applies to
  `mw search`, MCP `search_memory`, and every surface using the core scorer.

### Benchmarks

- **LongMemEval retrieval study** (#358): a public long-term memory benchmark
  (ICLR 2025, MIT) we did not write, run offline and deterministically. It is
  what exposed the recency problem: with recency off, our ranker matched plain
  BM25 and beat our own default.
- **Terminal-Bench harness** (#354): a Harbor agent that runs Claude Code on
  Terminal-Bench with and without MemoryWhale carried across tasks. Ready, not
  yet run; no results are claimed.

### Website

- A 3D ocean hero with a live recall demo that shows real `mw` output (#355, #356),
  and copy without em dashes (#357).

### Also fixed

- `mw context --last-error` uses a colon instead of an em dash:
  "You've hit this 2 times: a later run succeeded 1 of 2 times." (#357)

## Measured retrieval quality

Default ranking, before and after this release:

| Benchmark | 0.13.0 | 0.14.0 |
|---|---|---|
| LongMemEval NDCG@10 (public, 470 questions) | 0.802 | **0.883** |
| LongMemEval answer session in top 5 | 94.5% | **96.6%** |
| Term-overlap set recall@1 (30) | 0.522 | **0.822** |
| Shortcut eval `search_memory@1` (22) | 0.727 | **0.909** |
| Intent set recall@1 (18) | **0.833** | 0.778 |

The intent set loses one question, "the most reinforced lesson overall", whose
answer used to win partly because it was also the newest memory. Full details
are in [`benchmarks/longmemeval/`](../../benchmarks/longmemeval/README.md) and
[`benchmarks/BENCHMARKS.md`](../../benchmarks/BENCHMARKS.md).

## Upgrade and compatibility

- Ranking changes for queries without time words: results lean more on text
  relevance and less on age. Queries that ask about time rank as before.
- `memorywhale-core` 0.8.0 adds two public items; existing ones are unchanged.
  The CLI depends on this version, so core is republished to crates.io.
- No schema migration: schema 13 databases open as schema 13.

## What this release does not promise

- Time detection is a short word list. It misses some phrasings on purpose; a
  missed time question falls back to relevance ranking.
- LongMemEval is chat memory and measures retrieval only, not answer accuracy.
  It is evidence about ranking, not about debugging outcomes.
