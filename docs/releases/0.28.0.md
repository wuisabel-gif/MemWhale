# MemoryWhale 0.28.0 — Stopped Before It Fails

**Release date: November 17, 2026**

**Product: 0.28.0 · Rust core: 0.13.0 (unchanged) · SQLite schema: 17 (unchanged)**

0.27 made sure the lesson shown is the right one. This release asks whether a
lesson ever prevented anything, and the answer on one store was no. A lesson
can now stop a command before it runs, and a lesson no longer attaches to a
failure on a program name alone.

The CLI, web UI, and desktop app use product version **0.28.0**.
`memorywhale-core` stays at **0.13.0** and the store at schema **17**, so
nothing migrates.

## Install or upgrade

### The CLI

Prebuilt binaries cover Linux x86_64/aarch64 and macOS. The installer resolves
the current published release and verifies its published checksum:

```bash
(
  set -eu
  installer="$(mktemp)"
  trap 'rm -f "$installer"' EXIT
  curl -fsSL https://raw.githubusercontent.com/wuisabel-gif/MemWhale/7c3864c743cec9a8fa813dcc0b2459cc2859c849/install.sh -o "$installer"
  printf '%s  %s\n' '3e0cad72b29c1894d5ff5f7c30b099537f96501801c14b6320c12e169a3ac8d6' "$installer" | shasum -a 256 -c -
  sh "$installer"
)
```

To request this exact CLI release from crates.io after it is published:

```bash
cargo install memorywhale-cli --version 0.28.0 --locked
```

Or use Homebrew:

```bash
brew tap wuisabel-gif/memorywhale https://github.com/wuisabel-gif/MemWhale
brew install memorywhale
# If already installed:
brew update
brew upgrade memorywhale
```

The installer and Homebrew track their published release metadata rather than
pinning this document's version; check what was installed:

```bash
mw --version
mw doctor
```

From a source checkout, build all helpers from the repository root:

```bash
cargo build --release -p memorywhale-cli --bins
```

## What changed

### A lesson can stop a command before it runs (#499)

One store recorded the same shell mistake 47 times, on 22 days, in 21
directories: an agent printing a separator with `echo ====` under zsh, which
reads `=word` as a command lookup and fails the whole command with
`(eval):1: === not found`. MemoryWhale never helped, for two reasons.

The pre-run warning only fired when the same program had already failed in
the same directory, and this mistake kept happening somewhere new. And Claude
Code delivers a pre-run note together with the command's result, so even a
warning that fired arrived after the failure.

A lesson can now name the command text it is about. Start it with "when" and
the text in backticks:

```
$ mw remember 'when `echo ==`: zsh reads =word as a command lookup; quote the separator'
```

From then on, a Claude Code command that contains that text is stopped once,
in any directory, before it runs. The lesson is given as the reason, which
Claude Code shows to the model, so the agent rewrites the command instead of
failing first:

```
MemoryWhale stopped this command before it ran. Saved lesson (2 days ago):
when `echo ==`: zsh reads =word as a command lookup; quote the separator
Rewrite the command; to run it unchanged, send it again.
```

The stop happens once per command. The same command sent again within ten
minutes runs, so a lesson that is wrong for this case costs one resend. The
text is matched literally, outside heredoc bodies, and must be at least four
characters. Only approved lessons can stop a command. `mw doctor` counts the
stops and how many were followed by a command that passed:

```
ok   recall notes: on: 15 shown to agents, 1 followed, 1 worked; 4 stopped before running, 4 then passed
```

Other agents keep the existing note. Only Claude Code documents that the
model sees the reason for a denied command.

### A program name alone no longer attaches a lesson (#500)

On the same store, the last three lesson notes and two of the three pre-run
warnings were about something else. Each came from a scratch binary called
`check`: its one-word name matched the ordinary word "check" inside a lesson.
A program stem now counts only with its subcommand or first argument, such as
`gh pr` or `pgrep -f`. A match on the error text is unchanged.

## Tested

| What | Result |
|---|---|
| Stop before running | `a_lesson_naming_command_text_stops_that_command_once`: stopped in a directory with no history, runs when sent again, not stopped when quoted or inside a heredoc body, counted by `mw doctor`. |
| Replay on recorded history | 6,937 agent commands on a copy of one store, replayed through the pre-run hook with the one lesson above: all 47 occurrences stopped, and 1 other command stopped (the text sat inside a quoted remote command). |
| Lesson matching | `a_lesson_needs_whole_word_stem_matches_and_approval` now also rejects a one-word stem. |
| Workspace | 528 core and CLI tests pass; `cargo clippy -D warnings` is clean. |

## Upgrade and compatibility

- Nothing migrates. Stores stay at schema 17, and `memorywhale-core` is
  unchanged.
- `memorywhale-cli` adds `lesson_trigger` and `lesson_before`, and
  `RecallStats` gains `stopped` and `stopped_then_passed`.
- The Claude Code pre-run hook can now deny a command. It does so only for an
  approved lesson that opens with "when" and backticked text, and only once
  per command. `MEMORYWHALE_HOOK_FEEDBACK=0` still turns the hook off.
- A lesson that used to match on a one-word program name no longer does. Add
  the subcommand to the lesson, or start it with "when" and the command text.
- No setup is needed after upgrading; the installed hook picks this up.

## What this release does not promise

- A stop is a literal text match. It cannot tell a harmless use from a
  harmful one, which is why it happens once and a resend runs.
- The replay shows what would have been stopped on recorded history. It does
  not show that the agent's rewritten command then succeeds.
- MemoryWhale does not write these lessons for you. Someone has to notice
  the repeated mistake and save one sentence about it.
- Stops work in Claude Code only. Codex, Cursor, Gemini CLI, and Rho are
  unchanged.
- Lesson weights do not learn from outcomes yet.
- The macOS app is not notarized, so the first open needs **Open Anyway**.
