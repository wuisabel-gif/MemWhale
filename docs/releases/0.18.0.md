# MemoryWhale 0.18.0 — Recall in Every Agent

**Release date: October 5, 2026**

**Product: 0.18.0 · Rust core: 0.9.0 · SQLite schema: 13**

0.16 and 0.17 gave Claude Code and Cursor proactive recall: when an error comes
back, the agent is told what fixed it last time. 0.18 brings Codex in, and Rho
commands now arrive with real exit codes, so all four agents MemoryWhale
captures from can learn from what already failed.

The CLI, web UI, and desktop app use product version **0.18.0**.
`memorywhale-core` is **0.9.0**: it adds the `codex` agent identifier, which
changes the public `SUPPORTED_AGENTS` array from five entries to six. Existing
databases stay on schema **13**.

## Install or upgrade

Prebuilt binaries cover Linux x86_64/aarch64 and macOS. The installer resolves
the current published release and verifies its published checksum:

```bash
(
  set -eu
  installer="$(mktemp)"
  trap 'rm -f "$installer"' EXIT
  curl -fsSL https://raw.githubusercontent.com/wuisabel-gif/MemWhale/7c3864c743cec9a8fa813dcc0b2459cc2859c849/install.sh -o "$installer"
  printf '%s  %s\n' '3e0cad72b29c1894d5ff5f7c30b099537f96501801c14b6320c12e169a3ac8d6' "$installer" | shasum -a 256 -c -
  sh "$installer"
)
```

To request this exact CLI release from crates.io after it is published:

```bash
cargo install memorywhale-cli --version 0.18.0 --locked
```

Or use Homebrew:

```bash
brew tap wuisabel-gif/memorywhale https://github.com/wuisabel-gif/MemWhale
brew install memorywhale
# If already installed:
brew update
brew upgrade memorywhale
```

The installer and Homebrew track their published release metadata rather than
pinning this document's version; check what was installed. Make sure the chosen
binary directory is on `PATH` (`~/.local/bin` for the installer or
`~/.cargo/bin` for Cargo):

```bash
mw --version
mw doctor
```

From a source checkout, build all helpers from the repository root:

```bash
cargo build --release -p memorywhale-cli --bins
```

The CLI does not require the desktop shell's GTK/WebKit libraries. Windows
users can use WSL. See [Getting started](../guides/getting-started.md) and the
[Linux guide](../../linux/README.md) for platform setup and Debian packaging.

## What changed

### Codex: command capture and proactive recall (#397)

```bash
mw integrate codex --capture            # add the hook to ~/.codex/hooks.json
mw integrate codex --capture --check    # confirm it is installed
mw integrate codex --capture --revert   # remove only what MemoryWhale added
```

This adds one `PostToolUse` hook for Codex's `Bash` tool. Each shell command
Codex runs is recorded with its working directory and output, secret-scrubbed
before it is written, and searchable with `agent:codex`. When the output shows
an error that a later command fixed before, Codex gets the same one-line note
as Claude Code and Cursor, naming that fix. Your other Codex hooks are kept,
and `--dry-run` shows the change without writing.

Codex's documentation describes separate `exit_code`, `stdout`, and `stderr`
fields for the hook, but current Codex sends only the command's combined output,
with no exit code. Both shapes are accepted. Codex rows are stored with an
unknown exit, so they do not appear in `recent_errors` or
`mw context --last-error`, and the "passed after failing, save the lesson" note
does not fire for Codex. To make the fix note work anyway, hook feedback now
also checks commands with an unknown exit and looks for the error line in
stdout as well as stderr; a note still needs a recorded past fix.

### Rho: real exit codes and output (#396)

With Rho versions that send `payload.process` in `after_tool_use`, Rho commands
are stored with their real exit code, stdout, and stderr. They now count in
`--last-error`, failure fingerprints, and fix detection, like terminal capture.
When a signal ends the process with no output, Rho's failure message is kept.
Older Rho payloads work as before.

Matt Jiang, Rho's author, contributed this and added `payload.process` on the
Rho side ([matthewyjiang/rho#1395](https://github.com/matthewyjiang/rho/pull/1395)).
That change is merged in Rho but was not yet in a Rho release when 0.18.0 was
tagged; the [Rho guide](../../integrations/rho/README.md) will name the first
Rho version that includes it.

### Linux and Jetson setup (#398)

- The Jetson runbook and the SOP install from a release, Cargo, or a build from
  the repository root, covering all eight CLI binaries, instead of copying
  files out of the retired `src-tauri/src/bin` layout.
- LAN access to the dashboard is documented as `mw-serve --lan`, with the token
  from `serve.token` in the data directory (readable only by you) or
  `MEMORYWHALE_TOKEN`, pasted into the sign-in form and never into a URL.
- `linux/systemd/enable-dashboard.sh --lan` installs the dashboard service on
  the LAN without putting the token in the unit file. It no longer suggests an
  unauthenticated `--host 0.0.0.0` bind, which `mw-serve` refuses.

### Tests

`mw --help` and `-h`, and the friendly errors for incomplete `mw` arguments, now
have subprocess tests (#398).

## Upgrade and compatibility

- No migration: stores stay on schema 13.
- Codex capture is opt-in; nothing changes for Codex until you run
  `mw integrate codex --capture`. Existing Claude Code and Cursor hooks keep
  working, and pick up the stdout check when the binaries are upgraded.
- Rust users of `memorywhale-core`: `SUPPORTED_AGENTS` is now `[&str; 6]` and
  there is a new `AGENT_CODEX` constant. Code that matched on the array length
  needs updating.

## What this release does not promise

- Codex capture is tested against the payload in Codex's source and through the
  real `mw-remember` binary, not yet in a live Codex session.
- Codex rows have no exit code, so Codex failures are not counted as failures.
- Rho exit codes need a Rho release that includes rho#1395.
- Past fixes are matched on error text, and the suggested fix is the next
  successful different command, which is usually but not always the fix.
