# MemoryWhale 0.25.0 — Honest Answers

**Release date: November 1, 2026**

**Product: 0.25.0 · Rust core: 0.12.0 · SQLite schema: 17 (unchanged)**

MemoryWhale now says less when it knows less. A search that matches nothing
says so, instead of returning whatever was recent or important. A fix that
stopped working is no longer offered as a confirmed fix. This release also
adds a scorer for paired debugging trials.

The CLI, web UI, and desktop app use product version **0.25.0**.
`memorywhale-core` moves to **0.12.0**. The store stays at schema **17**, so
nothing migrates.

## Install or upgrade

### The CLI

Prebuilt binaries cover Linux x86_64/aarch64 and macOS. The installer resolves
the current published release and verifies its published checksum:

```bash
(
  set -eu
  installer="$(mktemp)"
  trap 'rm -f "$installer"' EXIT
  curl -fsSL https://raw.githubusercontent.com/wuisabel-gif/MemWhale/7c3864c743cec9a8fa813dcc0b2459cc2859c849/install.sh -o "$installer"
  printf '%s  %s\n' '3e0cad72b29c1894d5ff5f7c30b099537f96501801c14b6320c12e169a3ac8d6' "$installer" | shasum -a 256 -c -
  sh "$installer"
)
```

To request this exact CLI release from crates.io after it is published:

```bash
cargo install memorywhale-cli --version 0.25.0 --locked
```

Or use Homebrew:

```bash
brew tap wuisabel-gif/memorywhale https://github.com/wuisabel-gif/MemWhale
brew install memorywhale
# If already installed:
brew update
brew upgrade memorywhale
```

The installer and Homebrew track their published release metadata rather than
pinning this document's version; check what was installed:

```bash
mw --version
mw doctor
```

From a source checkout, build all helpers from the repository root:

```bash
cargo build --release -p memorywhale-cli --bins
```

## What changed

### Search abstains when nothing matches (#467)

Until now, a search returned its top-ranked rows even when none of them
contained the query, because recency and importance alone could rank a row.
A search with text now keeps only rows whose content matches it, and says
when there are none:

```
$ mw search qqq-nothing-zzz
Insufficient evidence: no content matches for "qqq-nothing-zzz". Try a more specific error or command.
```

The CLI, MCP's `search_memory`, the dashboard's search API, the TUI, and the
desktop app all use the same rule. Rows are filtered before the result limit,
so a recent unrelated row can no longer push a real match out. Browsing with
an empty query is unchanged. This drops rows with no content match; it is not
a calibrated confidence threshold, and a generic shared word still matches.

### A fix that stopped holding is not offered as confirmed (#468)

A recall hint names the command that fixed an error before. If the failing
command failed again after that fix and before the error came back, the fix
no longer gets a `confirmed fix:` or `possible fix:` label:

```
$ mw hint 'error: linker `cc` not found'
seen 2 times; worked 1 of 1 times, but a later rerun failed, exit 2; historical candidate: xcode-select --install
```

The error coming back is why a hint appears, so on its own it never counts
against the fix. When the fix held, the hint reads as before, including the
markers Delphin's `:fix` reads. Library callers can read the latest rerun
(run id, command, exit code, time, repository) from
`FixCandidate::verification`. The commit of that rerun is not captured and is
shown as unknown.

### A scorer for paired debugging trials (#469)

`benchmarks/release_gate/evaluate.py` scores cold and memory runs of the same
tasks: verified solves, wasted attempts, and misleading hints, counted
separately. Its gate passes only on 20 or more complete pairs of real model
runs, with more solves and no more wasted attempts with memory, and no
misleading hints. Fixture runs never pass. It makes no model calls. No model
trials have been run yet, so it makes no claim about this release.

## Tested

| What | Result |
|---|---|
| Search abstention | Positive and negative controls for the CLI (`search_abstention`) and MCP. The pstack playbook check now requires the abstention message. |
| Fix verification | `fix_verification` covers a passing rerun, a regression, an unknown exit, an error coming back (keeps `possible fix:`), and a failure between the fix and its return (drops it). The earlier hint tests pass unchanged. |
| Trial scorer | Four unit tests: fixture exclusion, misleading hints, incomplete or mismatched pairs, and no gain. |
| Workspace | 516 core and CLI tests pass; `cargo clippy -D warnings` is clean. |

## Upgrade and compatibility

- Nothing migrates. Stores stay at schema 17.
- `memorywhale-core` 0.12.0 adds `MemoryEngine::retrieve_matches`, with a
  default implementation; `retrieve` is unchanged.
- `memorywhale-cli`'s `fix_candidates` takes a third argument, the run being
  hinted about (`i64::MAX` for none), and `FixCandidate` gains `verification`.
- Scripts that expected rows from a search with no matching text now get the
  insufficient-evidence message or an empty result.

## What this release does not promise

- Semantic (embedding) search barely abstains: its similarity is almost always
  above zero. No threshold has been calibrated.
- The desktop app's search uses the new rule but was not tested by hand.
- A passing rerun is evidence the fix held, not proof it caused the fix.
- The trial scorer has no real model runs behind it yet.
- The macOS app is not notarized, so the first open needs **Open Anyway**.
