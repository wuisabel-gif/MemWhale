# MemoryWhale 0.21.0 — Fewer, Truer Hints

**Release date: October 20, 2026**

**Product: 0.21.0 · Rust core: 0.10.0 (unchanged) · SQLite schema: 15**

0.20 started measuring its own recall notes. Four days of real use on one
machine gave the first numbers: 711 commands captured from Claude Code, 40
failures, 8 notes shown, 0 followed, 0 worked. Every note pointed at a
bystander (`find …`, `ps aux`, `ls`, a `cd`), because a "possible fix" was the
next different command that passed, with no check that anything got fixed, and
because agents run one-shot scripts whose text never recurs. 0.21 fixes both.
On the same four days of data, those 8 notes become 0; the measurement is what
will show whether the notes that remain are worth following.

The CLI, web UI, and desktop app use product version **0.21.0**.
`memorywhale-core` stays **0.10.0**. Opening a store migrates it to schema
**15**, which recomputes every error fingerprint.

## Install or upgrade

Prebuilt binaries cover Linux x86_64/aarch64 and macOS. The installer resolves
the current published release and verifies its published checksum:

```bash
(
  set -eu
  installer="$(mktemp)"
  trap 'rm -f "$installer"' EXIT
  curl -fsSL https://raw.githubusercontent.com/wuisabel-gif/MemWhale/7c3864c743cec9a8fa813dcc0b2459cc2859c849/install.sh -o "$installer"
  printf '%s  %s\n' '3e0cad72b29c1894d5ff5f7c30b099537f96501801c14b6320c12e169a3ac8d6' "$installer" | shasum -a 256 -c -
  sh "$installer"
)
```

To request this exact CLI release from crates.io after it is published:

```bash
cargo install memorywhale-cli --version 0.21.0 --locked
```

Or use Homebrew:

```bash
brew tap wuisabel-gif/memorywhale https://github.com/wuisabel-gif/MemWhale
brew install memorywhale
# If already installed:
brew update
brew upgrade memorywhale
```

The installer and Homebrew track their published release metadata rather than
pinning this document's version; check what was installed. Make sure the chosen
binary directory is on `PATH` (`~/.local/bin` for the installer or
`~/.cargo/bin` for Cargo):

```bash
mw --version
mw doctor
```

From a source checkout, build all helpers from the repository root:

```bash
cargo build --release -p memorywhale-cli --bins
```

The CLI does not require the desktop shell's GTK/WebKit libraries. Windows
users can use WSL. See [Getting started](../guides/getting-started.md) and the
[Linux guide](../../linux/README.md) for platform setup and Debian packaging.

## What changed

### Evidence before a suggestion (#428)

A fix is suggested only when the failing program passed after it: in two
episodes, or in its only episode when a person typed the fix at a prompt. An
agent's single "fix" is not trusted; on the real data it was a coincidence
every time. Programs that only read (`ls`, `find`, `cat`, `grep`, `ps`,
`git status` and `git log`, inline `python3 -c` and heredoc scripts, `gh`,
`mw` itself) are never candidates. With no evidence, the hook says nothing.

The note quotes the fix's own step, not the script around it, at most 120
characters:

```text
MemoryWhale: this error was seen 3 times; worked 2 of 2 times, last run by Cursor just now, confirmed fix: xcode-select --install. Check whether it applies here.
MemoryWhale: this error was seen 2 times; worked once, run in a terminal 3 h ago, possible fix: brew install cmake. Check whether it applies here.
```

`possible fix` now means exactly one thing: you typed it yourself, and the
failing program passed after it.

### Agent commands are understood as scripts (#428)

Runs are compared by program stem, `program <first argument>`: `cargo build`,
`python3 plot.py`, `git push`. For a multi-step script the stem is the step the
error line names (`ls: … No such file` picks the `ls` step), else the last step
that is not read-only. `cd`, assignments, control words, `sudo`/`env`/`time`, a
leading `yes |`, heredoc bodies, and fragments broken by a quote are skipped.
Error fingerprints, fix evidence, the "passed after failing, save a lesson"
prompt, and the recall stats all use the stem, so a failure captured by an
agent and a fix typed at a prompt are one episode, and the same error can
finally be seen to recur across differently worded scripts.

### Smaller changes

- The lesson prompt looks back ten runs for the same stem in the same
  directory and quotes the command truncated to 80 characters.
- `mw context --last-error` and the MCP `similar_failures` tool fingerprint by
  stem, matching stored rows.

## Upgrade and compatibility

- Opening a store migrates it from schema 14 to 15: every error fingerprint is
  recomputed with the program stem. Nothing else changes, and nothing is
  deleted.
- `memorywhale-core` is unchanged at 0.10.0. `memorywhale-cli` gains
  `program_stem`, `stem_of_line`, `stem_for_failure`, `read_only_program`,
  `salient_error_line`, and `register_sql_functions`; `Failure` now carries a
  `stem` instead of `command` and `argv_json`, and `FixCandidate::trusted`
  is the suggestion rule.
- The note wording is unchanged for parsers: the command is last, after
  `confirmed fix:` or `possible fix:`. Delphin 0.5.2 needs no change.

## What this release does not promise

- Fewer notes is the point, so a first-time fix found by an agent is not
  suggested until it has worked twice. That is a deliberate trade of recall
  for precision; the stats will say whether it was the right one.
- Stems are a heuristic without a shell parser. Text inside quotes that
  contains `;` or a newline can still produce an odd stem for that run; the
  evidence rule keeps it from becoming a wrong suggestion.
- Recurrence was rare in the data studied (one recurring fingerprint in four
  days), so most of the value is in silence until errors repeat.
