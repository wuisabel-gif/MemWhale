# MemoryWhale 0.13.0 — Feedback-Aware, Portable Memory

**Release date: September 27, 2026**

**Product: 0.13.0 · Rust core: 0.7.0 · SQLite schema: 13**

0.13 makes retrieval feedback do something and makes memory move between
machines. Feedback recorded in 0.12 was display-only; now it can shape ranking,
and it travels with `import`/`push`/`pull` instead of being left behind.
Capture still writes the store; retrieval still reads it; core stays generic.

The CLI, web UI, and desktop app use product version **0.13.0**.
`memorywhale-core` is **0.7.0** (adds `encode_id`, the inverse of `decode_id`).
Existing databases stay on schema **13**; there is no migration.

## Install or upgrade


Prebuilt binaries cover Linux x86_64/aarch64 and macOS. The installer resolves
the current published release and verifies its published checksum:

```bash
(
  set -eu
  installer="$(mktemp)"
  trap 'rm -f "$installer"' EXIT
  curl -fsSL https://raw.githubusercontent.com/wuisabel-gif/MemWhale/7c3864c743cec9a8fa813dcc0b2459cc2859c849/install.sh -o "$installer"
  printf '%s  %s\n' '3e0cad72b29c1894d5ff5f7c30b099537f96501801c14b6320c12e169a3ac8d6' "$installer" | shasum -a 256 -c -
  sh "$installer"
)
```

To request this exact CLI release from crates.io after it is published:

```bash
cargo install memorywhale-cli --version 0.13.0 --locked
```

Or use Homebrew:

```bash
brew tap wuisabel-gif/memorywhale https://github.com/wuisabel-gif/MemWhale
brew install memorywhale
# If already installed:
brew update
brew upgrade memorywhale
```

The installer and Homebrew track their published release metadata rather than
pinning this document's version; check what was installed. Make sure the chosen
binary directory is on `PATH` (`~/.local/bin` for the installer or
`~/.cargo/bin` for Cargo):

```bash
mw --version
mw doctor
```

From a source checkout, build all helpers from the repository root:

```bash
cargo build --release -p memorywhale-cli --bins
```

The CLI does not require the desktop shell's GTK/WebKit libraries. Windows
users can use WSL. See [Getting started](../guides/getting-started.md) and the
[Linux guide](../../linux/README.md) for platform setup and Debian packaging.

## What changed

### Retrieval: feedback can shape ranking (opt-in)

- **Feedback-adjusted ranking** (#349): `mw search --use-feedback` (and MCP
  `search_memory` `use_feedback: true`) reorders results by your recorded
  feedback. Active `helpful` marks lift a memory; `irrelevant`/`outdated`/
  `contradicted` lower it, by a bounded amount that breaks near-ties without
  overriding a real relevance gap. It never rewrites the relevance score or
  filters results, and `--explain` shows the adjustment. Default ranking and
  output are unchanged unless you pass the flag.

### Memory: feedback and links travel between machines

- **Portable feedback and links** (#348): `mw import` / `mw pull` / `mw push`
  now carry `retrieval_feedback` and typed `memory_links`, remapping each
  memory's row id to its id on the destination. Rows whose target memory did
  not import are skipped and counted; re-import is idempotent. Feedback is no
  longer machine-local.

### Capture: recurring failures are recognized everywhere

- **Fingerprints on every capture path** (#351): `mw-remember`, the desktop
  app, `mw demo`, and `mw import` now store an error fingerprint for failed
  commands, computed from redacted stderr. Before this, only the recording
  shell set it, so `mw context --last-error` could report "First time hitting
  this" for an error you had already seen. Imported stores are backfilled.

### Integrations

- **Qwen Code** (#345), **OpenHands Software Agent SDK** (#346), and
  **Mistral Vibe** (#347) get MCP setup guides and verification scripts,
  bringing the verified total to 19 coding agents.

### Also changed

- README and landing page lead with a recall demo and the benchmark. (#352)
- Dependency updates: `ureq` 3 (#327), `rusqlite` 0.40 (#328), `toml_edit`
  0.25 (#329), `dirs` 6 (#330), `lucide-react` 1.x (#325).

## Measured retrieval quality

The published benchmark runs default ranking, which this release does not
change, so the 0.12.0 numbers stand. `--use-feedback` needs recorded feedback
to have any effect, and the synthetic benchmark records none; it is not
measured yet.

## Upgrade and compatibility

- `memorywhale-core` 0.7.0 adds `encode_id`; existing public items are
  unchanged. The CLI depends on this version, so core is republished for
  crates.io.
- No schema migration: schema 13 databases open as schema 13.
- Default search output and ranking are unchanged unless you pass
  `--use-feedback` (or `--mode` / `--ranking`).

## What this release does not promise

- Feedback ranking is a bounded, opt-in reorder, not a learned model.
- Transfer remaps row ids on import; it does not change the primary-key
  scheme. Cross-machine identity beyond import remains an RFC topic.
