# MemoryWhale 0.23.0 — MemoryWhale on Your Desktop

**Release date: October 26, 2026**

**Product: 0.23.0 · Rust core: 0.10.0 (unchanged) · SQLite schema: 17**

MemoryWhale now has a desktop app, and this is the first release that ships
it. It looks like the website, with the same ocean and 3D whale, and it shows
what your coding agents were told, the commands and output behind it, and the
lessons you saved. It stays in the menu bar and announces each new note or
warning as a hook writes it. The same history is also in the terminal, as
`mw recall`, and on the web dashboard's new `/recall` page.

The CLI, web UI, and desktop app use product version **0.23.0**.
`memorywhale-core` stays **0.10.0**. Opening a store migrates it to schema
**17**, which keeps the exact text of each note and warning.

## Install or upgrade

### The CLI

Prebuilt binaries cover Linux x86_64/aarch64 and macOS. The installer resolves
the current published release and verifies its published checksum:

```bash
(
  set -eu
  installer="$(mktemp)"
  trap 'rm -f "$installer"' EXIT
  curl -fsSL https://raw.githubusercontent.com/wuisabel-gif/MemWhale/7c3864c743cec9a8fa813dcc0b2459cc2859c849/install.sh -o "$installer"
  printf '%s  %s\n' '3e0cad72b29c1894d5ff5f7c30b099537f96501801c14b6320c12e169a3ac8d6' "$installer" | shasum -a 256 -c -
  sh "$installer"
)
```

To request this exact CLI release from crates.io after it is published:

```bash
cargo install memorywhale-cli --version 0.23.0 --locked
```

Or use Homebrew:

```bash
brew tap wuisabel-gif/memorywhale https://github.com/wuisabel-gif/MemWhale
brew install memorywhale
# If already installed:
brew update
brew upgrade memorywhale
```

The installer and Homebrew track their published release metadata rather than
pinning this document's version; check what was installed. Make sure the chosen
binary directory is on `PATH` (`~/.local/bin` for the installer or
`~/.cargo/bin` for Cargo):

```bash
mw --version
mw doctor
```

From a source checkout, build all helpers from the repository root:

```bash
cargo build --release -p memorywhale-cli --bins
```

The CLI does not require the desktop shell's GTK/WebKit libraries. Windows
users can use WSL. See [Getting started](../guides/getting-started.md) and the
[Linux guide](../../linux/README.md) for platform setup and Debian packaging.

### The desktop app

The release attaches the app next to the CLI archives, each with a `.sha256`:

| Platform | File |
| --- | --- |
| macOS, Apple silicon and Intel | `MemoryWhale-0.23.0-macos.dmg` |
| Linux x86_64, Debian and Ubuntu | `memorywhale-desktop_0.23.0_amd64.deb` |
| Linux x86_64, other distributions | `MemoryWhale-0.23.0-x86_64.AppImage` |

On macOS, open the disk image and drag MemoryWhale to Applications. The app is
signed ad hoc but not notarized, so the first time macOS says it cannot check
it: open **System Settings → Privacy & Security** and choose **Open Anyway**.
The app does not install the CLI; install that as above, then connect your
agents with `mw integrate claude` (or `codex`, `cursor`, `gemini`, `rho`). The
[desktop guide](../guides/desktop.md) has the details.

## What changed

### The desktop app (#446, #447, #448, #449, #450, #452)

The app reads the same local store the CLI and the agent hooks write to, and
redacts captured text again before showing it.

- **Home:** the website's ocean hero, with the beige device showing the last
  note an agent saw and its outcome; how recall is doing (notes shown,
  followed, worked; warnings and how many then passed); commands per agent;
  recent failures; the latest notes and warnings.
- **Search:** everything you and your agents ran, saw, or saved, ranked, with
  "why this result" and a link from a command hit to the command.
- **Recall:** every note and warning, headed by the program it was about
  ("Note after `cargo build` failed"), with the exact words, the agent, the
  folder, and what happened next.
- **Commands:** runs grouped by day, all or failures only, with a text filter.
  A run opens its output and the next five runs in the same folder, which is
  often the fix.
- **Lessons:** add one in your own words, approve one an agent saved for
  review, or delete one after a second click.
- **Menu bar:** closing the window keeps MemoryWhale running. Every five
  seconds it checks for a note or warning a hook wrote and shows a
  notification, such as "Warned claude before cargo build", with the exact text.

Type is a rounded face for reading and a round cursive script for titles, both
system fonts on macOS. Releases build the app on every tag (#450).

### What agents were told: `mw recall` and `/recall` (#441)

```bash
mw recall              # newest first
mw recall --limit 20
```

Each entry shows when the note or warning fired, which agent saw it, the
directory, the failing command, the exact text it was shown, and the outcome
read back from the runs that followed: `followed, worked`,
`followed, no pass yet`, `not followed`, `then passed`, or `no pass yet`. The
dashboard's recall line links to the same list on `/recall`. The exact text is
stored from this version on; older entries show without it.

### Command lines split like a shell (#441)

Separators and spaces inside quotes no longer break a command into fake steps,
so a commit message, an inline `python3 -c` script, or a path with a space gets
the right program stem. `echo "a && b; c" && cargo test` now reads as
`cargo test`.

### Codewhale capture with stock Codewhale (#292)

The capture bundle passed a native test against the released Codewhale 0.10.1,
which ships the execution receipt the adapter reads (Hmbown/Codewhale#6713).
Capture needs **Full Access** mode: Codewhale builds receipts only for
unsandboxed runs, so in Ask and Auto the hook fires with no receipt and nothing
is stored. Search over MCP works in every mode. See the
[capture verification report](../../integrations/codewhale/CAPTURE-VERIFICATION.md).

### Fixed

- The old desktop app's Demo Data button deleted every command run not linked
  to a case file from the real store. It is gone (#442).
- `npm run dev` and `npm run tauri:dev` showed a blank window (#444).

### Removed

- The desktop app's knowledge-galaxy graph, text import, and manual command
  form, with the commands and tables only they used, the dialog and fs plugins,
  and d3 (#448).

## Tested

| What | Result |
|---|---|
| Desktop app on macOS | A debug build ran over a backup copy of a real store (2,390 commands, 9 notes): every page, search, and the command drawer worked. Inserting a warning into the copy refreshed the open window within five seconds, and closing the window left the app running. |
| Release bundles | A build-only run of the release workflow built the universal `.dmg` (12 MB, signed ad hoc) and the Linux `.deb` and AppImage. |
| `mw recall` | Covered end to end by `mw_recall_lists_notes_after_the_hook_shows_one`, and on the dashboard by `recall_page_lists_events_and_handles_an_empty_store`. |
| Codewhale capture | Native pass with the official Codewhale 0.10.1 macOS binary in Full Access mode; Ask and Auto captured nothing, as the mode table in the report shows. |

## Upgrade and compatibility

- Opening a store migrates it from schema 16 to 17: `recall_hints` gains
  `text`. Nothing else changes, and earlier CLIs keep working on a migrated
  store.
- `memorywhale-core` is unchanged at 0.10.0. `memorywhale-cli` adds
  `recall_history` and `RecallEvent`.
- The desktop app opens the default store, or the one in
  `MEMORYWHALE_DATA_DIR`, and creates it private to your user if it is missing.

## What this release does not promise

- The macOS app is not notarized, so the first open needs **Open Anyway**.
- The Linux `.deb` and AppImage are built in CI but were not launched on a
  Linux desktop for this release. Linux has no Snell Roundhand or SF Rounded,
  so titles fall back to a generic cursive.
- The notification banner itself was not seen in testing; macOS asks for
  permission the first time.
- Codewhale capture works only in Full Access mode.
