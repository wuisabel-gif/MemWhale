# MemoryWhale 0.12.1 — Harden Secret Redaction

**Release date: September 25, 2026**

**Product: 0.12.1 · Rust core: 0.6.1 · SQLite schema: 13**

A security-hardening patch on top of [0.12.0](0.12.0.md). No schema change, no
new features, and no intentional behavior change beyond redaction and
publishability.

## Why upgrade

- **Secrets split by terminal controls are now redacted (#337).** A control
  sequence placed inside a secret label — for example `tok<ESC>en=…` — could
  previously slip past the redaction matcher and be stored or exported in the
  clear. Redaction now strips terminal controls before and after matching, in
  the shared `memorywhale-core` privacy path that every capture and export
  surface uses, not only in case files and recipes. This closes the class of
  bypass found while reviewing the 0.12.0 retrieval features.

## Also in this release

- **Reviewer action pinned to v0.4.0 (#320)** in the Second-Opinion CI
  workflow, with the integration guide and its consistency check kept in sync.
- **Dependency updates (#321, #326):** grouped minor and patch bumps for the
  npm and Cargo dependency sets.

## Publishability

`memorywhale-core` is republished as **0.6.1** because `memorywhale-cli` 0.12.1
uses its new `privacy` module. Prefer 0.12.1 for
`cargo install memorywhale-cli` and Homebrew-from-source. GitHub tarballs for
0.12.0 already include the fix through the workspace path dependency.

```bash
cargo install memorywhale-cli --version 0.12.1 --locked
```
