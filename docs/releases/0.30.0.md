# MemoryWhale 0.30.0 — One Memory, Four Assistants

**Release date: November 22, 2026**

**Product: 0.30.0 · Rust core: 0.13.0 (unchanged) · SQLite schema: 17 (unchanged)**

Until now MemoryWhale remembered what a terminal did. This release adds a
second, opt-in memory for what you have told your assistants: a preference, a
decision, a standing instruction. One action brings in what you already said
to Claude Code, Codex, ChatGPT, and Claude; you review each statement; and
the ones you approve can be handed to any of them.

Debugging memory is unchanged, and a store that never runs a `mw knowledge`
command behaves as it did in 0.29.

The CLI, web UI, and desktop app use product version **0.30.0**.
`memorywhale-core` stays at **0.13.0** and the store at schema **17**, so
nothing migrates.

## Install or upgrade

### The CLI

Prebuilt binaries cover Linux x86_64/aarch64 and macOS. The installer resolves
the current published release and verifies its published checksum:

```bash
(
  set -eu
  installer="$(mktemp)"
  trap 'rm -f "$installer"' EXIT
  curl -fsSL https://raw.githubusercontent.com/wuisabel-gif/MemWhale/7c3864c743cec9a8fa813dcc0b2459cc2859c849/install.sh -o "$installer"
  printf '%s  %s\n' '3e0cad72b29c1894d5ff5f7c30b099537f96501801c14b6320c12e169a3ac8d6' "$installer" | shasum -a 256 -c -
  sh "$installer"
)
```

To request this exact CLI release from crates.io after it is published:

```bash
cargo install memorywhale-cli --version 0.30.0 --locked
```

Or use Homebrew:

```bash
brew tap wuisabel-gif/memorywhale https://github.com/wuisabel-gif/MemWhale
brew install memorywhale
# If already installed:
brew update
brew upgrade memorywhale
```

The installer and Homebrew track their published release metadata rather than
pinning this document's version; check what was installed:

```bash
mw --version
mw doctor
```

From a source checkout, build all helpers from the repository root:

```bash
cargo build --release -p memorywhale-cli --bins
```

## What changed

### One action to bring in what you have said (#523, #525, #526)

```
$ mw knowledge import
mw: read 216 conversation file(s) holding 7115 message(s) you wrote.
    119 new statement(s) are waiting for review (claude_code 119).
    6 already known; 0 skipped as secret-shaped; 0 file(s) unreadable.
    No ChatGPT or Claude chat export was found in ~/Downloads.
    ChatGPT: Settings, Data controls, Export data. Claude: Settings, Privacy, Export data.
    Save the download there and run this again.
    Nothing is used until you approve it: mw knowledge pending
```

In the desktop app the same thing is the **Import my conversations** button
on the new Knowledge page.

| Source | Where it looks | What it takes |
| --- | --- | --- |
| Claude Code memory files | `~/.claude/projects/<project>/memory/*.md` | Each file's one-line description. |
| Claude Code transcripts | `~/.claude/projects/<project>/*.jsonl` | Sentences you typed that state a preference, a fact about you, a decision, a project fact, or a standing instruction. |
| Codex sessions | `~/.codex/sessions` | The same. |
| ChatGPT and Claude chat | A data export saved in `~/Downloads` | The same, from your messages. |

ChatGPT and Claude do not let another program read your conversations, so
those two need one step from you first: request the data export in the
product's settings and save the download. The Knowledge page has a button
that opens each product's help page for it.

Only what you typed is read. Assistant replies, tool output, questions, code
blocks, and long pasted text are skipped, and a sentence that still looks
like it holds a secret after masking is not stored.

### You review every statement (#525)

```
$ mw knowledge pending
#2  preference  proposed  from claude_chat 2026-01-01
    From now on explain the tradeoffs before recommending
#1  preference  proposed  from chatgpt 2023-11-14
    I prefer answers with a short summary first
```

`approve` uses a statement and lets assistants be shown it. `keep` uses it
but keeps it private. `reject` drops it, and it is never proposed again, even
if a later import finds it. Each takes ids or `all`. There is no setting that
approves statements automatically.

### Hand it to any assistant (#525, #527)

```
$ mw knowledge export --into ~/.codex/AGENTS.md
mw: wrote the knowledge block in /Users/ada/.codex/AGENTS.md; the rest of the file is unchanged.
```

`mw knowledge export` prints the approved statements as a Markdown block to
paste into ChatGPT or Claude. With `--into` it writes the block into an
instruction file that Claude Code or Codex reads. Only the section between
its own markers is written, so the lines you wrote stay as they are, and a
second run replaces the block instead of adding another. Each statement is
quoted as a fact with its source and date, and the block says it is not an
instruction.

A statement about a project or a decision belongs to the folder it was said
in and is included only with `--project <that folder>`.

### Kept apart from debugging memory (#523)

Knowledge lives in its own tables. The command stop, failure notes, the six
MCP tools, `mw export`, and `mw memory publish` do not read them, so an
imported sentence can never stop a command or be attached to a failure. The
tables are created the first time a knowledge command runs; the store's
schema version does not change.

## Tested

| What | Result |
|---|---|
| Review and limits | A proposal is unread until approved; a rejection survives re-import; a project's statements are not shown to another project; a private statement is left out of the context block; a deleted statement is gone from every read. |
| Untrusted text | A secret-shaped sentence is skipped. An imported sentence telling an assistant to ignore its instructions is stored as quoted text and never reaches the command stop. |
| Source formats | Each of the four formats yields only what the person typed. |
| One action | Through the `mw` binary against a throwaway home: import finds every source, review decides what is exported, `--into` twice leaves one block and the handwritten lines intact, and a second import proposes nothing. |
| Real local data | On one machine, 216 files and 7,115 typed messages gave 119 candidates in about 5 seconds: 114 from Claude Code memory files and 5 from transcripts. |
| Interface | The Knowledge page test and the 14 existing interface tests pass. |

## Upgrade and compatibility

- Nothing migrates. Stores stay at schema 17, and `memorywhale-core` is
  unchanged.
- Nothing is imported until you run `mw knowledge import` or press the
  button. Nothing is used until you approve it.
- `memorywhale-cli` adds the `knowledge` module.
- An older binary opening a store with the new tables ignores them.

## What this release does not promise

- **The ChatGPT and Claude export parsers are unverified.** No real export
  was available, so they follow the publicly described structure of
  `conversations.json`. They are tested against files built to that
  structure, not against a real one.
- **Transcripts yield little.** Extraction is a fixed list of English
  sentence patterns that favors a short review queue: 5 statements from
  about 7,000 typed messages on one machine. Claude Code's memory files are
  the useful source today.
- **Limits are not a security boundary.** Project and private limits decide
  what a configured client is shown. Any program running as you can read the
  store file.
- **No connection to built-in memory.** MemoryWhale does not read or write
  the memory inside ChatGPT or Claude, and it does not offer them an MCP
  connection, which would need a public address.
- Archived Codex sessions are compressed and are not read.
- The design proposal for this feature is still open for review in pull
  request #522; details may change.
- The Knowledge page was checked in a browser preview with sample data, not
  inside the packaged desktop app.
- The macOS app is not notarized, so the first open needs **Open Anyway**.
