# MemoryWhale 0.11.0 — Explainable Debugging Evidence

**Release date: September 20, 2026**

**Product: 0.11.0 · Rust core: 0.5.0 · SQLite schema: 10**

MemoryWhale keeps debugging evidence usable when you switch terminals,
worktrees, or coding agents. This release adds compare, ranking explanation,
project timelines, local handoff export, and additional thin client
integrations. Capture still writes the store; retrieval still reads it;
integrations stay outside core.

The CLI, web UI, and desktop app use product version **0.11.0**.
`memorywhale-core` remains **0.5.0**. Existing databases stay on schema **10**.

## Install or upgrade

Prebuilt binaries cover Linux x86_64/aarch64 and macOS. The installer resolves
the current published release and verifies its published checksum:

```bash
(
  set -eu
  installer="$(mktemp)"
  trap 'rm -f "$installer"' EXIT
  curl -fsSL https://raw.githubusercontent.com/wuisabel-gif/MemWhale/7c3864c743cec9a8fa813dcc0b2459cc2859c849/install.sh -o "$installer"
  printf '%s  %s\n' '3e0cad72b29c1894d5ff5f7c30b099537f96501801c14b6320c12e169a3ac8d6' "$installer" | shasum -a 256 -c -
  sh "$installer"
)
```

To request this exact CLI release from crates.io after it is published:

```bash
cargo install memorywhale-cli --version 0.11.0 --locked
```

Or use Homebrew:

```bash
brew tap wuisabel-gif/memorywhale https://github.com/wuisabel-gif/MemWhale
brew install memorywhale
# If already installed:
brew update
brew upgrade memorywhale
```

The installer and Homebrew track their published release metadata rather than
pinning this document's version; check what was installed. Make sure the chosen
binary directory is on `PATH` (`~/.local/bin` for the installer or
`~/.cargo/bin` for Cargo):

```bash
mw --version
mw doctor
```

From a source checkout, build all helpers from the repository root:

```bash
cargo build --release -p memorywhale-cli --bins
```

The CLI does not require the desktop shell's GTK/WebKit libraries. Windows
users can use WSL. See [Getting started](../guides/getting-started.md) and the
[Linux guide](../../linux/README.md) for platform setup and Debian packaging.

## What changed

The changes fit the four areas in the [architecture](../architecture.md):

### Capture: inspectable health and extra opt-in hooks

```bash
mw doctor
mw doctor capture
```

`mw doctor capture` runs an isolated probe. It does not enable hooks, inspect
the normal store as a mutation target, or write production records. (#305)

Cursor Shell hook capture is opt-in for supported shell events. (#278)
Codewhale's MemoryWhale-side plugin and execution capture remain opt-in and
separate from MCP retrieval. (#287, #288)

### Memory: hand off evidence without moving the database

```bash
mw handoff --ids c:12,s:4 --format markdown --output ./handoff.md
mw retention report
```

`mw handoff` exports explicitly selected command-run and session IDs as
Markdown or JSON. It refuses to overwrite an existing file, does not follow
symlink parents, and performs no upload. (#302)

`mw retention report` inventories retained sessions, runs, screenshots,
bookmarks, and pending notes. It names future purge targets and does not
delete them. (#306)

### Retrieval: compare, explain, and timeline

```bash
mw compare 12 18
mw timeline --project my-build
```

`mw compare` shows field-level differences between two recorded command runs.
Free-form terminal-bound fields are sanitized and truncated before display.
(#299)

MCP `search_memory` accepts optional `explain: true` so a client can see why
a hit ranked where it did. Default ranking is unchanged. (#300)

`mw timeline --project <name>` reads a project timeline from a snapshot that
does not mutate WAL sidecars. Exact `project:<name>` matching applies. (#307)

### Interfaces: more MCP clients, still thin

Waku Agent and Kimi Code CLI gain MemoryWhale-side MCP setup guides, example
config, optional debugging skills, and offline asset tests. (#293, #298)

- Waku keeps its own semantic/episodic/procedural memory. MemoryWhale is
  debugging evidence beside that, not a replacement.
- Kimi Code transport and configuration are documented; a native Kimi client
  call is not claimed in this release.

Portable MCP setup and explicit local skills remain Interfaces adapters. (#274)

## Upgrade and compatibility

- Back up your store before upgrading. This release does not add a SQLite
  migration; schema 10 databases open as schema 10.
- `memorywhale-core` stays `0.5.0`. There is no breaking Rust API change in
  this product release.
- Re-run `mw doctor` after upgrading integrations. A healthy MCP server does
  not prove a capture hook is installed.
- Case files, command recipes, retrieval feedback, contradiction flags,
  search modes, and Bayesian ranking are not included.

## What this release does not promise

- Stock Codewhale hosts are not claimed to capture without the documented
  MemoryWhale plugin and any host receipt fields that host requires.
- Waku verification uses a scripted model client, not a live hosted Waku
  Memory replacement.
- Kimi Code native execution is pending; the shipped tests cover MemoryWhale
  assets and MCP configuration.
- Task-start recall, automatic failure lookup, and pre-compaction saving remain
  unimplemented client-orchestration ideas.
