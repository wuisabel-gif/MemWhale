# MemoryWhale 0.19.0 — Recall in Gemini

**Release date: October 12, 2026**

**Product: 0.19.0 · Rust core: 0.10.0 · SQLite schema: 13**

Gemini CLI joins Claude Code, Cursor, and Codex: one command connects it, and
with capture on it learns from what already failed, with real exit codes.
`mw doctor` now shows whether capture is actually working, not just
configured, and recall notes say "possible fix" instead of claiming to know
the fix.

The CLI, web UI, and desktop app use product version **0.19.0**.
`memorywhale-core` is **0.10.0**: `SUPPORTED_AGENTS` becomes a slice, the last
time adding an agent changes its type. Existing databases stay on schema
**13**.

## Install or upgrade

Prebuilt binaries cover Linux x86_64/aarch64 and macOS. The installer resolves
the current published release and verifies its published checksum:

```bash
(
  set -eu
  installer="$(mktemp)"
  trap 'rm -f "$installer"' EXIT
  curl -fsSL https://raw.githubusercontent.com/wuisabel-gif/MemWhale/7c3864c743cec9a8fa813dcc0b2459cc2859c849/install.sh -o "$installer"
  printf '%s  %s\n' '3e0cad72b29c1894d5ff5f7c30b099537f96501801c14b6320c12e169a3ac8d6' "$installer" | shasum -a 256 -c -
  sh "$installer"
)
```

To request this exact CLI release from crates.io after it is published:

```bash
cargo install memorywhale-cli --version 0.19.0 --locked
```

Or use Homebrew:

```bash
brew tap wuisabel-gif/memorywhale https://github.com/wuisabel-gif/MemWhale
brew install memorywhale
# If already installed:
brew update
brew upgrade memorywhale
```

The installer and Homebrew track their published release metadata rather than
pinning this document's version; check what was installed. Make sure the chosen
binary directory is on `PATH` (`~/.local/bin` for the installer or
`~/.cargo/bin` for Cargo):

```bash
mw --version
mw doctor
```

From a source checkout, build all helpers from the repository root:

```bash
cargo build --release -p memorywhale-cli --bins
```

The CLI does not require the desktop shell's GTK/WebKit libraries. Windows
users can use WSL. See [Getting started](../guides/getting-started.md) and the
[Linux guide](../../linux/README.md) for platform setup and Debian packaging.

After upgrading, re-run the `mw integrate` commands you use (for example
`mw integrate claude`, `mw integrate codex --capture`) so hooks point at the
stable `/opt/homebrew/bin` path from 0.18.1; this release also fixes that
refresh for Codex MCP entries.

## What changed

### Gemini CLI: MCP, command capture, and proactive recall (#404)

```bash
mw integrate gemini            # MemoryWhale MCP in ~/.gemini/settings.json
mw integrate gemini --capture  # AfterTool hook for run_shell_command
```

Both support `--check`, `--dry-run`, and `--revert`, and keep your other
Gemini settings. Captured commands are stored with their working directory,
output, and **exit code**: Gemini puts an `Exit Code:` line in the tool result
when a command fails, so a finished command without one exited 0. Gemini rows
count as failures in `recent_errors` and `mw context --last-error`, and both
recall notes work: the possible fix for a known error, and the request to save
a lesson when a command passes right after failing. Gemini asks you to approve
a new hook once. See the [Gemini CLI guide](../../integrations/gemini-cli/README.md).

### `mw doctor` shows what is actually captured (#409)

Each connected agent gets a `last captured` line from the database: how long
ago, and how many recent commands carried an exit code, or `never` with the
next step. A hook can be configured and still capture nothing (Codex skips a
hook until you trust it in `/hooks`); doctor now says so. A `recall notes`
line says whether hook feedback is on.

### "Possible fix", not "the fix was" (#409)

A recalled fix is the next different command that passed after the failure.
That is usually the fix, not always, so notes now read:

```text
MemoryWhale: this error was seen once; a later command passed, possible fix: xcode-select --install. Check whether it applies here.
```

[Delphin](https://github.com/wuisabel-gif/Delphin) 0.5.1 reads both forms for
`:fix`.

### Fixes

- Codex MCP entries refresh in place after an upgrade. 0.18.1 compared them as
  JSON, but Codex stores TOML, so `mw integrate codex` still asked for
  `--revert` (#411).
- The release check requires plain `@handle` contributor mentions, which
  GitHub needs to list contributors on the release page (#403).

## Upgrade and compatibility

- No migration: stores stay on schema 13.
- Rust users of `memorywhale-core`: `SUPPORTED_AGENTS` is now `&[&str]`
  instead of `[&str; 6]`, with a new `AGENT_GEMINI`. Code that relied on the
  array length needs a small change; adding agents will not change the type
  again.
- Tools that parse recall notes for `the fix was:` should also accept
  `possible fix:`.

## What this release does not promise

- Integrations marked "not yet verified live" above are tested against their
  documented or source-level payloads, not in a real session.
- Codex rows have no exit code, so Codex failures are not counted as failures.
- A possible fix is the next different command that passed; it is not
  confirmed to be the fix.
