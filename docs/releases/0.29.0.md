# MemoryWhale 0.29.0 — A Head Start

**Release date: November 19, 2026**

**Product: 0.29.0 · Rust core: 0.13.0 (unchanged) · SQLite schema: 17 (unchanged)**

0.28 let a saved lesson stop a command before it runs, but someone still had
to notice the repeated mistake and write the lesson, a new install had
nothing to recall, and the stop worked in one agent. This release takes on
all three: MemoryWhale drafts the lesson, a new store can start from your
shell history, and the stop works in Codex.

The CLI, web UI, and desktop app use product version **0.29.0**.
`memorywhale-core` stays at **0.13.0** and the store at schema **17**, so
nothing migrates.

## Install or upgrade

### The CLI

Prebuilt binaries cover Linux x86_64/aarch64 and macOS. The installer resolves
the current published release and verifies its published checksum:

```bash
(
  set -eu
  installer="$(mktemp)"
  trap 'rm -f "$installer"' EXIT
  curl -fsSL https://raw.githubusercontent.com/wuisabel-gif/MemWhale/7c3864c743cec9a8fa813dcc0b2459cc2859c849/install.sh -o "$installer"
  printf '%s  %s\n' '3e0cad72b29c1894d5ff5f7c30b099537f96501801c14b6320c12e169a3ac8d6' "$installer" | shasum -a 256 -c -
  sh "$installer"
)
```

To request this exact CLI release from crates.io after it is published:

```bash
cargo install memorywhale-cli --version 0.29.0 --locked
```

Or use Homebrew:

```bash
brew tap wuisabel-gif/memorywhale https://github.com/wuisabel-gif/MemWhale
brew install memorywhale
# If already installed:
brew update
brew upgrade memorywhale
```

The installer and Homebrew track their published release metadata rather than
pinning this document's version; check what was installed:

```bash
mw --version
mw doctor
```

From a source checkout, build all helpers from the repository root:

```bash
cargo build --release -p memorywhale-cli --bins
```

## What changed

### Lessons are drafted for you (#511)

On one store the same shell mistake failed 47 times over five weeks before a
person noticed and wrote one sentence about it. MemoryWhale had every failure
on disk the whole time.

It now does the noticing. When the same error has failed on three or more
days and no lesson covers it, MemoryWhale drafts a lesson and puts it in the
review queue. Drafting runs when an agent's command fails, and on demand:

```
$ mw memory suggest
#12  when `echo ==`: this failed 19 times on 13 days with: (eval):1: ===== not found
#13  `Error: Cannot find module 'docx'` came back on 3 days (3 failures); no fix is recorded

2 draft lesson(s) are waiting for review; run `mw memory pending`.
```

Nothing uses a draft until you approve it with `mw memory approve <id>`, and
`mw doctor` says when drafts are waiting.

A draft says what was observed and never guesses a fix. An earlier
measurement found that guessing a fix from "failed, then passed" was sensible
about 2 times in 81, so that was not built. Instead:

- When text from the error starts a word in every failing command, the draft
  opens with "when" and that text. Approving it stops the command before it
  runs, with the count and the error as the reason.
- Otherwise the draft quotes the error, so it is shown the next time that
  error appears.

Three kinds of error are left alone: one about a path, which groups unrelated
mistakes; one a saved lesson already covers; and one drafted before, so a
rejected draft does not come back. To add the fix yourself, reject the draft
and save your own sentence with `mw remember`.

### A new store can start from your shell history (#513)

A new install has an empty store, so the first search finds nothing. The
history your shell already keeps can fill it:

```
$ mw import --shell-history
mw: imported 4812 command(s) from /Users/ada/.zsh_history (0 already there).
    Commands and their times only: shell history has no output or exit codes. Secrets are masked, and nothing leaves this machine. Try `mw search <word>`.
```

It reads `$HISTFILE`, else `~/.zsh_history` or `~/.bash_history`, or the file
you pass, and takes the newest 5000 commands unless `--limit N` says
otherwise. The first `mw` on a new machine asks once whether to import, and
`mw doctor` points at the command while the store is empty. Nothing is
imported without a yes.

Each imported row is a command and its time, marked `source:shell-history`.
History has no output, exit code, or directory, so those stay empty. Commands
pass the same masking as recorded ones, and a variable named like a secret,
such as `API_TOKEN=...`, loses its value. Running the import again adds only
what is new.

### The stop works in Codex (#510)

A lesson that opens with "when" and command text in backticks now stops a
matching Codex command once, before it runs. Codex accepts the same denial as
Claude Code on its `PreToolUse` hook and passes the reason to the model as
the command's output. `mw integrate codex` already installs that hook, so
nothing new needs setting up beyond trusting the hooks in Codex (`/hooks`).

### Smaller changes

- The README demo now shows a command being stopped before it runs (#514).
- The coverage job in CI skips one unreadable profile instead of failing
  (#515).

## Upgrade and compatibility

- Nothing migrates. Stores stay at schema 17, and `memorywhale-core` is
  unchanged.
- After upgrading, the first failed agent command may add drafts for errors
  already in your history. They wait in `mw memory pending` and change
  nothing until approved.
- `memorywhale-cli` adds `draft_recurring_lessons`, `LessonDraft`,
  `parse_shell_history`, and `import_shell_history`. Draft markers are
  `recall_hints` rows of kind `drafted`, kept out of recall history and the
  stats.
- `mw-remember --before-hook codex` can now deny a command, by the same rule
  as Claude Code. `MEMORYWHALE_HOOK_FEEDBACK=0` still turns the hook off.
- No setup is needed after upgrading.

## What this release does not promise

- A draft is an observation with no fix in it. A person or an agent still
  has to supply the fix, or approve the draft as it stands.
- Drafting needs a non-zero exit code, so it does not yet see Codex failures,
  which arrive without one.
- The Codex stop is covered by a test and by Codex's documented hook
  behavior. It has not been watched in a live Codex session here.
- Imported history cannot be recalled as a fix: with no exit codes,
  MemoryWhale cannot tell which of those commands failed.
- The first-run import prompt was not exercised by an automated test.
- The macOS app is not notarized, so the first open needs **Open Anyway**.
