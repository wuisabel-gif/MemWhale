# MemoryWhale 0.28.1 — A Tested Interface

**Release date: November 19, 2026**

**Product: 0.28.1 · Rust core: 0.13.0 (unchanged) · SQLite schema: 17 (unchanged)**

A patch release made of four contributions from @MayurK-cmd. The web and
desktop interface gets its first real test suite and moves to React 19, and
the docs explain what happens to a recording when the terminal dies. Recall,
capture, and the command line behave as they did in 0.28.0.

The CLI, web UI, and desktop app use product version **0.28.1**.
`memorywhale-core` stays at **0.13.0** and the store at schema **17**, so
nothing migrates.

## Install or upgrade

### The CLI

Prebuilt binaries cover Linux x86_64/aarch64 and macOS. The installer resolves
the current published release and verifies its published checksum:

```bash
(
  set -eu
  installer="$(mktemp)"
  trap 'rm -f "$installer"' EXIT
  curl -fsSL https://raw.githubusercontent.com/wuisabel-gif/MemWhale/7c3864c743cec9a8fa813dcc0b2459cc2859c849/install.sh -o "$installer"
  printf '%s  %s\n' '3e0cad72b29c1894d5ff5f7c30b099537f96501801c14b6320c12e169a3ac8d6' "$installer" | shasum -a 256 -c -
  sh "$installer"
)
```

To request this exact CLI release from crates.io after it is published:

```bash
cargo install memorywhale-cli --version 0.28.1 --locked
```

Or use Homebrew:

```bash
brew tap wuisabel-gif/memorywhale https://github.com/wuisabel-gif/MemWhale
brew install memorywhale
# If already installed:
brew update
brew upgrade memorywhale
```

The installer and Homebrew track their published release metadata rather than
pinning this document's version; check what was installed:

```bash
mw --version
mw doctor
```

From a source checkout, build all helpers from the repository root:

```bash
cargo build --release -p memorywhale-cli --bins
```

### The desktop app

The release attaches the app next to the CLI archives, each with a `.sha256`:

| Platform | File |
| --- | --- |
| macOS, Apple silicon and Intel | `MemoryWhale-0.28.1-macos.dmg` |
| Linux x86_64, Debian and Ubuntu | `memorywhale-desktop_0.28.1_amd64.deb` |
| Linux x86_64, other distributions | `MemoryWhale-0.28.1-x86_64.AppImage` |

The macOS app is signed ad hoc but not notarized: the first time, open
**System Settings → Privacy & Security** and choose **Open Anyway**. See the
[desktop guide](../guides/desktop.md).

## What changed

### The interface has tests (#493, #494)

The React interface had almost no automated tests, so a change to it could
only be checked by hand. There is now a jsdom harness with a stand-in for the
Tauri bridge that fails loudly on any call a test did not expect. On top of
it, 14 tests drive the interface the way a person does: opening sections from
the sidebar, searching, opening a run's details, and reviewing recall.

```bash
npm test
```

### React 19 (#491)

The interface moves from React 18.3 to 19.3, with `react`, `react-dom`, and
their type packages upgraded together. The new tests pass on it, and the
type check and the production build are clean.

The same change fixes the site check, which built its root folder from a URL
path and so failed in a checkout whose path contains a space.

### Live autosave and recovery, explained (#492)

The [debugging guide](../guides/debugging.md) and the
[CLI reference](../reference/cli.md) now say what `mw --live` writes and how
often, what happens when the terminal closes or an SSH connection drops
before `exit`, and when to reach for `mw-recover`.

## Upgrade and compatibility

- Nothing migrates. Stores stay at schema 17, and `memorywhale-core` is
  unchanged.
- No Rust code changed. The `mw` binaries differ from 0.28.0 only in their
  version number.
- Building the interface from source now needs React 19; run `npm ci` after
  pulling.
- No setup is needed after upgrading.

## What this release does not promise

- The interface tests run in jsdom against a stand-in for the desktop bridge.
  They do not start the real desktop app or a browser.
- Stops still work in Claude Code only, and MemoryWhale still does not write
  lessons for you.
- The macOS app is not notarized, so the first open needs **Open Anyway**.
