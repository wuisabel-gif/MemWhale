# MemoryWhale 0.29.1 — Patched Dependencies

**Release date: November 22, 2026**

**Product: 0.29.1 · Rust core: 0.13.0 (unchanged) · SQLite schema: 17 (unchanged)**

A patch release for one security advisory in a dependency of the desktop app,
plus routine dependency updates. Nothing in MemoryWhale's own behavior
changes.

The CLI, web UI, and desktop app use product version **0.29.1**.
`memorywhale-core` stays at **0.13.0** and the store at schema **17**, so
nothing migrates.

## Install or upgrade

### The CLI

Prebuilt binaries cover Linux x86_64/aarch64 and macOS. The installer resolves
the current published release and verifies its published checksum:

```bash
(
  set -eu
  installer="$(mktemp)"
  trap 'rm -f "$installer"' EXIT
  curl -fsSL https://raw.githubusercontent.com/wuisabel-gif/MemWhale/7c3864c743cec9a8fa813dcc0b2459cc2859c849/install.sh -o "$installer"
  printf '%s  %s\n' '3e0cad72b29c1894d5ff5f7c30b099537f96501801c14b6320c12e169a3ac8d6' "$installer" | shasum -a 256 -c -
  sh "$installer"
)
```

To request this exact CLI release from crates.io after it is published:

```bash
cargo install memorywhale-cli --version 0.29.1 --locked
```

Or use Homebrew:

```bash
brew tap wuisabel-gif/memorywhale https://github.com/wuisabel-gif/MemWhale
brew install memorywhale
# If already installed:
brew update
brew upgrade memorywhale
```

The installer and Homebrew track their published release metadata rather than
pinning this document's version; check what was installed:

```bash
mw --version
mw doctor
```

From a source checkout, build all helpers from the repository root:

```bash
cargo build --release -p memorywhale-cli --bins
```

### The desktop app

The release attaches the app next to the CLI archives, each with a `.sha256`:

| Platform | File |
| --- | --- |
| macOS, Apple silicon and Intel | `MemoryWhale-0.29.1-macos.dmg` |
| Linux x86_64, Debian and Ubuntu | `memorywhale-desktop_0.29.1_amd64.deb` |
| Linux x86_64, other distributions | `MemoryWhale-0.29.1-x86_64.AppImage` |

The macOS app is signed ad hoc but not notarized: the first time, open
**System Settings → Privacy & Security** and choose **Open Anyway**. See the
[desktop guide](../guides/desktop.md).

## What changed

### The `url` advisory (#520)

RUSTSEC-2026-0592, published November 20, 2026, reports a stack overflow in
`Url::origin()` on nested `blob:` URLs in `url` 2.5.8. MemoryWhale's desktop
app pulls that crate in through Tauri. This release moves it to 2.5.9, the
patched version, along with `form_urlencoded` 1.2.3.

The `mw` command-line tools do not depend on `url`, so the CLI was not
affected. If you use the desktop app, upgrade it.

### Dependency updates (#518, #519)

Patch-level updates to Tauri (2.12.7), its notification and opener plugins,
`tauri-build`, `ureq`, and `regex` on the Rust side, and to the Tauri
JavaScript packages, Vite, Vitest, Playwright, `lucide-react`, and the
testing library on the interface side.

## Tested

| What | Result |

| Workspace | Core and CLI tests, the interface tests, and the release package smoke test pass in CI. |

## Upgrade and compatibility

- Nothing migrates. Stores stay at schema 17, and `memorywhale-core` is
  unchanged.
- No MemoryWhale source code changed. The `mw` binaries differ from 0.29.0
  in their version number and in patch versions of `ureq` and `regex`.
- No setup is needed after upgrading.

## What this release does not promise

- No one here reproduced the overflow against MemoryWhale's desktop app.
  The upgrade follows the advisory's fixed version.
- The audit still lists unmaintained-crate warnings that have no fixed
  upgrade yet, such as `chrono`. They are warnings, not vulnerabilities.
- The macOS app is not notarized, so the first open needs **Open Anyway**.
