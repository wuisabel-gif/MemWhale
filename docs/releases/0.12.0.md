# MemoryWhale 0.12.0 — Retrieval You Can Trust

**Release date: TBD (milestone target October 14, 2026)**

**Product: 0.12.0 · Rust core: 0.6.0 · SQLite schema: 13**

<!-- DRAFT: sections marked TODO are filled in as each PR lands. -->

MemoryWhale already stores debugging evidence well. This release is about
retrieval you can rely on: choose what kind of memory a search returns, record
whether a result helped, rank with that feedback when you opt in, and see when
two memories disagree. Capture still writes the store; retrieval still reads
it; integrations stay outside core.

The CLI, web UI, and desktop app use product version **0.12.0**.
`memorywhale-core` is **0.6.0**. Existing databases migrate to schema **13**.

## Install or upgrade

Prebuilt binaries cover Linux x86_64/aarch64 and macOS. The installer resolves
the current published release and verifies its published checksum:

```bash
(
  set -eu
  installer="$(mktemp)"
  trap 'rm -f "$installer"' EXIT
  curl -fsSL https://raw.githubusercontent.com/wuisabel-gif/MemWhale/7c3864c743cec9a8fa813dcc0b2459cc2859c849/install.sh -o "$installer"
  printf '%s  %s\n' '3e0cad72b29c1894d5ff5f7c30b099537f96501801c14b6320c12e169a3ac8d6' "$installer" | shasum -a 256 -c -
  sh "$installer"
)
```

To request this exact CLI release from crates.io after it is published:

```bash
cargo install memorywhale-cli --version 0.12.0 --locked
```

Or use Homebrew:

```bash
brew tap wuisabel-gif/memorywhale https://github.com/wuisabel-gif/MemWhale
brew install memorywhale
# If already installed:
brew update
brew upgrade memorywhale
```

The installer and Homebrew track their published release metadata rather than
pinning this document's version; check what was installed. Make sure the chosen
binary directory is on `PATH` (`~/.local/bin` for the installer or
`~/.cargo/bin` for Cargo):

```bash
mw --version
mw doctor
```

From a source checkout, build all helpers from the repository root:

```bash
cargo build --release -p memorywhale-cli --bins
```

The CLI does not require the desktop shell's GTK/WebKit libraries. Windows
users can use WSL. See [Getting started](../guides/getting-started.md) and the
[Linux guide](../../linux/README.md) for platform setup and Debian packaging.

## What changed

### Retrieval: explicit modes, feedback, and opt-in ranking

- **Search modes** (#309): `mw search <text> --mode evidence|lessons|recipes|failures`
  and MCP `search_memory` `mode` narrow results to one kind of memory. Modes
  are enforced locally; an explicit mode never takes the external MemPalace
  path.
- **Retrieval feedback** (#304, #333): `mw feedback add <memory-id>
  helpful|irrelevant|outdated|contradicted [--actor NAME]` records local,
  attributable feedback on a result. `mw feedback list|show|undo` reviews or
  reverses it. In 0.12 feedback is recorded for review only; it does not
  change ranking yet. Feedback is deleted with its memory, and `mw pull` /
  `mw push` report skipped records rather than transferring them.
- **Bayesian ranking** (#310): opt-in `--ranking bayesian` / MCP
  `ranking: "bayesian"` combines the existing similarity, recency,
  importance, reinforcement, and task signals as log-odds, and `--explain`
  shows each signal's log-odds term. The score is a
  `posterior_proxy`, not a calibrated probability. The default ranking is
  unchanged.

### Memory: contradictions, case files, and recipes

- **Contradiction flags** (#308): `mw contradictions <a> <b>` flags two
  memories that share terms but differ on a negation cue, once per pair.
  `mw contradictions list|confirm|reject` reviews them. Memories are never
  changed, and flags are deleted with their memories.
- **Case files** (#301): `mw case create --title T --command-ids 1,2 ...`
  groups an ordered set of command runs with observations, a conclusion, and
  open questions. `mw case list|show|export` (JSON or `--format markdown`)
  redacts secrets and strips terminal controls. Case-linked runs are kept by
  `mw delete`, `mw prune`, and the desktop demo reset.
- **Command recipes** (#303): `mw recipe save --run 12,19 --description X`
  saves a reusable command from verified runs. `mw recipe list|show|copy`
  browses it, and nothing is executed. A recipe keeps its own payload, so
  pruning a source run only drops that provenance link.

### Also fixed

- **Codewhale capture** (#335): a replay check that matched hex IDs by
  prefix could silently drop a capture (`call_1` after `call_10`). IDs are
  now compared exactly.

## Measured retrieval quality

Deterministic benchmark (`cargo run -p memorywhale-core --example benchmark -- benchmarks/`),
same corpus and gold sets as 0.11:

| set | ranking | recall@1 | recall@5 | MRR |
|---|---|---|---|---|
| term-overlap (30 queries) | default | 0.522 | 0.961 | 0.747 |
| term-overlap (30 queries) | **bayesian** | **0.789** | **0.994** | **0.933** |
| intent (18 queries) | default | **0.833** | 1.000 | **0.935** |
| intent (18 queries) | bayesian | 0.778 | 1.000 | 0.907 |

Bayesian ranking is much better when the answer depends on matching words, and
slightly worse when recency, importance, or task context decides it. That's
why it stays opt-in and the default ranking is unchanged. Details are in
[`benchmarks/BENCHMARKS.md`](../../benchmarks/BENCHMARKS.md).

## Upgrade and compatibility

- Back up your store before upgrading. Opening a store with 0.12.0 migrates
  it from schema 10 to 13: 11 retrieval feedback, 12 case files, 13 command
  recipes. Older binaries cannot open a migrated store.
- `memorywhale-core` 0.6.0 adds `Ranking::Bayesian` and the contradiction
  module. Existing public items are unchanged.
- Default search output and ranking are unchanged unless you pass `--mode` or
  `--ranking`.

## What this release does not promise

- Bayesian scores are a ranking proxy, not probabilities or an authorization
  signal.
- Contradiction flags are heuristics that need review. They are not
  verified conflicts.
- Feedback stays local and does not affect ranking in this release.
