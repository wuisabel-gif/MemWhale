# MemoryWhale 0.18.1 — Recall That Survives Upgrades

**Release date: October 11, 2026**

**Product: 0.18.1 · Rust core: 0.9.0 (unchanged) · SQLite schema: 13**

A patch for everyone who installed MemoryWhale with Homebrew and connected an
agent with `mw integrate`. Upgrade, then re-run your `mw integrate` commands
once.

## The problem

`mw integrate` wrote the resolved, versioned path to its helpers, for example
`/opt/homebrew/Cellar/memorywhale/0.18.0/bin/mw-remember`, into
`~/.claude/settings.json`, `~/.rho/hooks.toml`, `~/.codex/hooks.json`, and the
Codex and Cursor MCP entries. Homebrew deletes that folder when it cleans up
after the next upgrade. Agent hooks are designed never to break the agent, so
capture then stopped without any error, and the Codex and Cursor MCP entries
pointed at a missing program.

## What changed (#402)

- `mw integrate` now writes the stable name on your `PATH` for the same
  program (`/opt/homebrew/bin/mw-remember`, `/opt/homebrew/bin/mw-mcp`), which
  survives upgrades.
- Re-running `mw integrate claude`, `rho`, `codex`, `cursor`, or
  `<client> --capture` updates an existing install in place when its old path
  is gone, is a versioned Homebrew install, or is the same file. A different
  helper that still exists still needs `--revert` first, as before.
- `mw doctor` lists Codex and Cursor (MCP entry and capture hook) and reports
  an entry as stale when it points at a missing or no-longer-current program.

## Upgrade

```bash
brew update && brew upgrade memorywhale
mw integrate claude          # and any of: rho, codex, cursor, codex --capture, cursor --capture
mw doctor
```

If an upgrade already removed the old folder, re-running `mw integrate` is
what restores capture. Codex asks you to trust a changed hook once: run
`/hooks` in Codex and trust the MemoryWhale hook.

`cargo install memorywhale-cli --version 0.18.1 --locked` and the installer
in the [README](../../README.md#install) work as for 0.18.0.
