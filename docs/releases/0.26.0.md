# MemoryWhale 0.26.0 — Lessons First

**Release date: November 8, 2026**

**Product: 0.26.0 · Rust core: 0.13.0 · SQLite schema: 17 (unchanged)**

A lesson you saved now comes first. When an error comes back,
`mw context --last-error` shows the lesson you wrote for it, and search ranks
that lesson above the raw failures. The recall score is also honest now: a
note counts as followed only when its fix actually ran. Semantic search can
finally say it found nothing.

The CLI, web UI, and desktop app use product version **0.26.0**.
`memorywhale-core` moves to **0.13.0**. The store stays at schema **17**, so
nothing migrates.

## Install or upgrade

### The CLI

Prebuilt binaries cover Linux x86_64/aarch64 and macOS. The installer resolves
the current published release and verifies its published checksum:

```bash
(
  set -eu
  installer="$(mktemp)"
  trap 'rm -f "$installer"' EXIT
  curl -fsSL https://raw.githubusercontent.com/wuisabel-gif/MemWhale/7c3864c743cec9a8fa813dcc0b2459cc2859c849/install.sh -o "$installer"
  printf '%s  %s\n' '3e0cad72b29c1894d5ff5f7c30b099537f96501801c14b6320c12e169a3ac8d6' "$installer" | shasum -a 256 -c -
  sh "$installer"
)
```

To request this exact CLI release from crates.io after it is published:

```bash
cargo install memorywhale-cli --version 0.26.0 --locked
```

Or use Homebrew:

```bash
brew tap wuisabel-gif/memorywhale https://github.com/wuisabel-gif/MemWhale
brew install memorywhale
# If already installed:
brew update
brew upgrade memorywhale
```

The installer and Homebrew track their published release metadata rather than
pinning this document's version; check what was installed:

```bash
mw --version
mw doctor
```

From a source checkout, build all helpers from the repository root:

```bash
cargo build --release -p memorywhale-cli --bins
```

## What changed

### Saved lessons lead context and search (#481, #482)

Before, a lesson saved with `mw remember` was invisible to
`mw context --last-error`, which looked only for a fix command, and search
ranked it below the failures it explained:

```
## This error
You've hit this 2 times: a later run succeeded 1 of 2 times. [5e69ab21]
Recall: seen 2 times, no fix recorded yet
```

Now the lesson leads, matched the same way agent notes and pre-run warnings
match it:

```
## This error
You've hit this 2 times: a later run succeeded 1 of 2 times. [5e69ab21]
Saved lesson (just now): linker cc not found -> run: xcode-select --install
$ mw search linker cc not found
 41%  [note · terminal] #3000000001 linker cc not found -> run: xcode-select --install
 37%  [command · terminal] #1000000001 cargo ["cargo","build"] os:macos runtime:host error: linker `cc` not found
```

Saved notes load at importance 0.8, above a failed command's 0.65. They still
need a content match to appear. `mw hint` is unchanged, so the fix markers
Delphin's `:fix` reads are unaffected.

### An honest recall score (#477)

`mw doctor`, `mw recall`, and `/recall` counted a note as followed when a later
run had the same program stem as the fix. Inline scripts share a stem
(`python3 -`), so any later heredoc counted, and a note without a fix matched
any setup-only line such as `cd /tmp`. A note now counts as followed only when
its fix runs: the same command, or the same stem when that stem names
something specific. On a backup copy of a real store, the score went from
12 shown, 4 followed, 2 worked to 12 shown, 1 followed, 1 worked.

### Semantic search can abstain (#479)

With embeddings on (the desktop app with Ollama running), similarity is a
cosine, which is almost never zero, so search never said "Insufficient
evidence". A row scored by embeddings now needs a cosine above 0.5. Measured
with `nomic-embed-text` on the recall benchmark, every relevant pair scored
0.528 or more, and 7 of 10 off-topic questions now abstain. Keyword search is
unchanged.

## Upgrade and compatibility

- Nothing migrates. Stores stay at schema 17.
- `memorywhale-core` 0.13.0 adds `SEMANTIC_MATCH_FLOOR`; `BuiltinEngine`
  overrides `retrieve_matches`. `retrieve` is unchanged.
- `memorywhale-cli` adds `follows_fix` and the `mw_follows` SQL function.
- Saved notes rank higher in search, so scripts that read the first search
  result may now see a note where they saw a command.
- The recall score in `mw doctor` may drop after upgrading. The old number
  counted unrelated commands.

## What this release does not promise

- On a real store, 0.26 still suggests no fix for recent agent failures,
  because they rarely recur. Hints stay quiet rather than wrong.
- The semantic floor does not separate technical off-topic questions from real
  matches (they scored 0.515 to 0.543); it was measured on 37 memories with one
  model.
- The pre-run warning has not yet been confirmed in a live Claude Code session.
- The desktop app's search was not tested by hand.
- The macOS app is not notarized, so the first open needs **Open Anyway**.
