# MemoryWhale 0.27.0 — Lessons You Can Trust

**Release date: November 13, 2026**

**Product: 0.27.0 · Rust core: 0.13.0 (unchanged) · SQLite schema: 17 (unchanged)**

0.26 put saved lessons first. This release makes sure the lesson shown is the
right one, written by who it says, and reviewed before it is used. It fixes a
lesson being attached to an unrelated command, adds a review queue in the
terminal, and lets lessons travel with a repository.

The CLI, web UI, and desktop app use product version **0.27.0**.
`memorywhale-core` stays at **0.13.0** and the store at schema **17**, so
nothing migrates.

## Install or upgrade

### The CLI

Prebuilt binaries cover Linux x86_64/aarch64 and macOS. The installer resolves
the current published release and verifies its published checksum:

```bash
(
  set -eu
  installer="$(mktemp)"
  trap 'rm -f "$installer"' EXIT
  curl -fsSL https://raw.githubusercontent.com/wuisabel-gif/MemWhale/7c3864c743cec9a8fa813dcc0b2459cc2859c849/install.sh -o "$installer"
  printf '%s  %s\n' '3e0cad72b29c1894d5ff5f7c30b099537f96501801c14b6320c12e169a3ac8d6' "$installer" | shasum -a 256 -c -
  sh "$installer"
)
```

To request this exact CLI release from crates.io after it is published:

```bash
cargo install memorywhale-cli --version 0.27.0 --locked
```

Or use Homebrew:

```bash
brew tap wuisabel-gif/memorywhale https://github.com/wuisabel-gif/MemWhale
brew install memorywhale
# If already installed:
brew update
brew upgrade memorywhale
```

The installer and Homebrew track their published release metadata rather than
pinning this document's version; check what was installed:

```bash
mw --version
mw doctor
```

From a source checkout, build all helpers from the repository root:

```bash
cargo build --release -p memorywhale-cli --bins
```

## What changed

### A lesson no longer attaches to the wrong command (#490)

On a real store, exactly one pre-run warning had ever been shown, and it was
wrong. A `for` loop running `t=$(pdftotext -f $p …)` was told that a program
called `-f $p` had failed "with ``", followed by a saved lesson about using
`pkill -f` over ssh, which had nothing to do with it.

Three things went wrong, and all are fixed. The flag `-f` was read as the
program name; a token starting with `-` is never a program now. The lesson
matched because "f p" appears inside "pkill -f / pgrep -f"; a lesson now
matches a program name on whole words. And the warning printed an empty error;
with no error line it now ends after the time.

A lesson still waiting for review could also lead a note or warning. Only
approved lessons are used now, as search already did.

### Review lessons from the terminal (#495)

A lesson an agent saves through the MCP `remember` tool waits for review.
Until now that meant the dashboard or the TUI pane, and nothing said the queue
had anything in it:

```
$ mw doctor
  WARN lessons: 1 waiting for review; run `mw memory pending`
$ mw memory pending
#1  just now  by repo
    linker cc not found -> run: xcode-select --install

mw memory approve <id>   use it in notes, warnings, and search
mw memory reject <id>    delete it
$ mw memory approve 1
mw: memory #1 approved; notes, warnings, and search now use it.
```

`approve` and `reject` act only on lessons in the queue, so `reject` cannot
delete a lesson already in use.

A lesson saved with `mw remember` from Claude Code's shell was labeled as
written by you. It is now labeled `claude-code`. It still takes effect right
away, because a shell command is what the skill tells the agent to run. Other
agents are not detected yet.

### Lessons that travel with a repository (#496)

```
$ mw memory publish
mw: wrote 1 lesson(s) to ~/api/.memorywhale/lessons.md. Read it, then commit it to share.
$ cat .memorywhale/lessons.md
# MemoryWhale lessons

Lessons saved for this repository. Run `mw memory adopt` to add them to your local review queue.

- linker cc not found -> run: xcode-select --install
```

`publish` writes only lessons that are approved, permanent, and saved inside
this repository, redacted, and keeps lines other people added. On another
machine, or for a teammate after a pull:

```
$ mw memory adopt
mw: 1 new lesson(s) from .memorywhale/lessons.md are waiting for review; run `mw memory pending`.
```

Adopted lessons go to the review queue and are not used until approved. The
file is whatever someone could commit, and a lesson is text that MemoryWhale
later shows to an agent, so it is treated as untrusted: sanitized like any
capture, control bytes stripped, 500 characters per lesson, 256 KiB per file.

## Upgrade and compatibility

- Nothing migrates. Stores stay at schema 17, and `memorywhale-core` is
  unchanged.
- `memorywhale-cli` adds `publish_repo_lessons`, `adopt_repo_lessons`, and
  `REPO_LESSONS_FILE`.
- `mw memory` with no action prints a longer usage line that now starts with
  `mw memory pending`.
- Lessons already saved from an agent's shell keep their old "human" label;
  only new ones are labeled.

## What this release does not promise

- MemoryWhale does not draft lessons for you. Measured on a real store, 81
  commands passed right after failing, and only about 2 would have produced a
  sensible draft, so a lesson is still something a person or agent writes.
- Only Claude Code is recognized when an agent runs `mw remember` in a shell.
- `adopt` protects against text reaching an agent unreviewed. It does not
  judge whether a lesson is true; that is what the review is for.
- Lesson weights do not learn from outcomes yet; there are too few recorded
  outcomes to fit them honestly.
- The pre-run warning has not yet been confirmed in a live Claude Code session.
- The macOS app is not notarized, so the first open needs **Open Anyway**.
