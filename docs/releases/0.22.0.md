# MemoryWhale 0.22.0 — Recall Before It Fails

**Release date: October 21, 2026**

**Product: 0.22.0 · Rust core: 0.10.0 (unchanged) · SQLite schema: 16**

Until now MemoryWhale spoke after a command failed. 0.22 also speaks before:
when an agent is about to run a program that failed in this directory, has not
passed since, and MemoryWhale has a saved lesson or a fix with evidence for
that error, the agent sees one line before the command runs. Nothing is
blocked, each failure is warned about once, and on a real store the hook is
silent almost always. Saved lessons now lead every note.

The CLI, web UI, and desktop app use product version **0.22.0**.
`memorywhale-core` stays **0.10.0**. Opening a store migrates it to schema
**16**, which adds two columns to the recall-stats table.

## Install or upgrade

Prebuilt binaries cover Linux x86_64/aarch64 and macOS. The installer resolves
the current published release and verifies its published checksum:

```bash
(
  set -eu
  installer="$(mktemp)"
  trap 'rm -f "$installer"' EXIT
  curl -fsSL https://raw.githubusercontent.com/wuisabel-gif/MemWhale/7c3864c743cec9a8fa813dcc0b2459cc2859c849/install.sh -o "$installer"
  printf '%s  %s\n' '3e0cad72b29c1894d5ff5f7c30b099537f96501801c14b6320c12e169a3ac8d6' "$installer" | shasum -a 256 -c -
  sh "$installer"
)
```

To request this exact CLI release from crates.io after it is published:

```bash
cargo install memorywhale-cli --version 0.22.0 --locked
```

Or use Homebrew:

```bash
brew tap wuisabel-gif/memorywhale https://github.com/wuisabel-gif/MemWhale
brew install memorywhale
# If already installed:
brew update
brew upgrade memorywhale
```

The installer and Homebrew track their published release metadata rather than
pinning this document's version; check what was installed. Make sure the chosen
binary directory is on `PATH` (`~/.local/bin` for the installer or
`~/.cargo/bin` for Cargo):

```bash
mw --version
mw doctor
```

From a source checkout, build all helpers from the repository root:

```bash
cargo build --release -p memorywhale-cli --bins
```

The CLI does not require the desktop shell's GTK/WebKit libraries. Windows
users can use WSL. See [Getting started](../guides/getting-started.md) and the
[Linux guide](../../linux/README.md) for platform setup and Debian packaging.

## What changed

### Recall before it fails (#436)

```bash
mw integrate claude              # adds the PreToolUse hook to ~/.claude/settings.json
mw integrate codex --capture     # adds a PreToolUse group next to the capture hook
```

`mw-remember --before-hook claude|codex` runs on Claude Code's and Codex's
`PreToolUse` event. It reads the command about to run, finds the most recent
failure of the same program (by stem, so `cd x && cargo build` and
`cargo build` match) in the same directory, and stays silent unless all of
these hold: the program has not passed since, the failure has not been warned
about already, and MemoryWhale has a saved lesson or a fix that meets the
evidence rule from 0.21. Then it adds one line of context:

```text
MemoryWhale, before you run this: `cargo build` failed here 2 h ago with `error: linker `cc` not found`. Worked 2 of 2 times, last run by Codex 2 days ago, confirmed fix: xcode-select --install. Consider that before retrying.
```

Programs that only read are never warned about. `MEMORYWHALE_HOOK_FEEDBACK=0`
turns warnings off together with the notes. Existing installs gain the hook
the next time you run `mw integrate claude` or `mw integrate codex --capture`;
`mw doctor` reports an install without it as stale. Codex asks you to trust
the changed hooks once. Gemini CLI's `BeforeTool` hook has no way to add
context without blocking the command, so Gemini keeps only the after-the-fact
note.

### Lessons first (#436)

A note or warning that matches a saved lesson, by program stem or by a
fragment of the error line (ignoring punctuation, so `` linker `cc` not found ``
matches "linker cc not found"), opens with the lesson. A matching lesson alone
is enough for a note, even with no fix evidence: what a person concluded is
worth more than what happened to pass next.

### Recall stats (#436)

`mw doctor`, the dashboard, and the MCP `stats` tool add how many warnings
were shown and how many were followed by the warned program passing within the
next five runs: `recall notes: on: 12 shown to agents, 9 followed, 7 worked;
3 warned before a command, 2 then passed`.

## Upgrade and compatibility

- Opening a store migrates it from schema 15 to 16: `recall_hints` gains
  `kind` and `since_run_id`. Nothing else changes.
- `memorywhale-core` is unchanged at 0.10.0. `memorywhale-cli` gains
  `recall_before`, `matching_lesson`, `agent_hook::before_command`, and two
  fields on `RecallStats`.
- Re-run `mw integrate claude` (and restart Claude Code) or
  `mw integrate codex --capture` (and trust the hooks in `/hooks`) to get the
  pre-run hook.

## What this release does not promise

- A warning needs the same evidence as a note: a fix seen to work twice, or
  once when a person typed it. A first-time failure, or one whose fix was only
  ever run by an agent once, gets no warning.
- Lesson matching is a text heuristic: a lesson that does not mention the
  program or the error's wording is not found.
- Whether Claude Code and Codex surface `PreToolUse` context in practice is
  taken from their documentation; the live-session check is still open.
